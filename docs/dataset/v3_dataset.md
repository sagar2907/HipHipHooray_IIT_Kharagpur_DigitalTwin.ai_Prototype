# Dataset v3 — production-grade synthetic plant data

Generated by three seeded scripts; everything regenerates exactly:

```bash
cd scripts
python build_process_dataset.py    # Tier 1: process/quality telemetry
python build_flow_dataset.py       # Tier 2: line flow event logs
python build_truth.py              # Tier 3: ground-truth labels (slow; use --workers)
```

Design rule for every element here: **it exists to enable one specific
measurable claim.** The claim-per-element tables are below. Anything you
cannot attach a claim to does not belong in this dataset.

Two structural rules:

1. **Observed vs hidden.** Files at the top level of each tier are what a
   real plant emits — nothing in them uses knowledge a plant lacks. Every
   `hidden/` directory holds ground truth (fault onsets, true values, dark
   -station events) used ONLY for scoring. An automated test
   (`tests/test_twin.py`) fails if a truth column leaks into an observed file.
2. **Calibrate on `holdout/`, develop on the main set, report headline
   numbers on `firewall/`.** The firewall sets use structurally different
   degradation mathematics (Wiener process vs gamma process) — a model that
   memorised the development generator degrades there, measurably.

---

## Tier 1 — `process/` (4 tool families, 12 fault conditions)

| File | Rows | What it is |
|---|---|---|
| `nutrunner.csv` | ~320k | Open-Protocol-style fastening results: program id, target/spec, torque, angle, current, temp, cycle, OK/NOK verdict, batch counter |
| `spotweld.csv` | ~200k | weld current, voltage, resistance, energy, cap-wear counter |
| `adhesive.csv` | ~140k | flow, pressure, bead width, material temp |
| `pressfit.csv` | ~140k | peak force, displacement at peak, curve slope |
| `quality_results.csv` | ~11k | end-of-line events — **only what EOL caught** (true counts are hidden) |
| `maintenance_log.csv` | ~90 | bench visits with as-found / as-left Cmk, technician shift |
| `material_lots.csv` | ~17 | fastener lot per VIN range; 2 lots out of spec |
| `holdout/` | 16 tools | all-healthy, separate seed — **threshold calibration happens here** |
| `firewall/` | 12 tools | Wiener-process damage — **headline numbers reported here** |
| `hidden/` | — | per-tool truth, per-op true values, EOL truth, imperfection log |

**Timestamps carry per-controller clock skew (±3 s)**, rows are dropped
(0.2%) and duplicated (0.05%), and one tool has NULL/spike bursts — all
logged in `hidden/imperfection_log.csv` so robustness is measurable, not
assumed.

**The two numbers that carry the sensor story** (from `hidden/ground_truth.csv`):

- `sensor_bias` tools: thousands of true defects, **>95% passed as OK** by the
  controller (it judges the lying sensor). Detectable only via secondary channels.
- `pure_transducer_drift` tools: ~25 true defects, **>1,000 good parts falsely
  rejected**. Recalibration is the complete fix — and the classifier can prove
  which case it is (torque moves, current does not).

Claim-per-condition:

| Condition | Claim |
|---|---|
| gradual_wear / spread_only / sudden_shift / overtorque / intermittent | v2 taxonomy: detector cannot overfit one signature |
| sensor_bias | monitoring the primary channel alone is structurally blind |
| pure_transducer_drift | the recalibration-vs-repair decision is provable from data |
| lubrication_loss | two-stage fault: secondaries lead the primary — early warning lives in "irrelevant" channels |
| post_calibration_reset | detector must NOT alarm on a service reset (false-alarm class nobody models) |
| batch_material_shift | cross-tool correlation separates material faults from tool faults |
| intermittent_connector | sensor-integrity faults vs process faults |

## Tier 2 — `flow/` (102 runs: 96 shifts across 4 layouts + 6 multi-shift)

Per run: `unit_scan.csv`, `station_state.csv`, `buffer_level.csv`,
`andon_log.csv`, `rework_log.csv`, `calendar.csv` (observed — a plant knows
its schedule) and `hidden/` (full logs incl. 3 dark stations, fault truth).

Simulator features and their claims:

| Feature | Claim |
|---|---|
| Rework loop (EOL fail → repair bay → retest) | WIP dynamics with rework are materially different; its absence is a tell |
| Shift calendar + post-break warm-up | breaks are the only backlog-drain mechanism; warm-up is a clock-correlated confound |
| Changeover wave, andon stops, PM window | the constraint moves on *schedules* as well as randomly — some shifts are predictable in advance |
| Parallel station pair (L3) | detection logic must survive non-series topology |
| material_starvation / quality_hold faults | constraints that are NOT "a station got slower" |
| 4 layouts (L1 20+merge, L2 30+2merge, L3 parallel, L4 15) | layout-transfer experiment — unclaimed in the literature |
| 30 no-fault L1 shifts | false-alarm rate with a defensible confidence interval |
| 69/102 runs with consecutive dark pairs | the dark-block localisation claim is testable at scale |

## Tier 3 — `truth/`

| File | Label | Method |
|---|---|---|
| `sensitivity.csv` | per-30-min-block primary/secondary constraint + full **marginal-gain vector** | station sped up 20% **only within the scored block** (windowed perturbation + CRN ⇒ clean counterfactual), 4 replications averaged |
| `persistence.csv` | constraint episodes and reign lengths | powers the persistence filter (alert only on constraints worth walking to) |
| `forecast_labels.csv` | constraint at +30/60/90 min | the accuracy-versus-horizon curve |
| `intervention.csv` | paired-CRN outcomes: no-fix vs fix-at-onset vs fix-at-break | prescription evaluated with distributions, not one lucky run |

Why per-block perturbation matters: v2 labels perturbed a station for the
whole shift, so a late block's label inherited hours of accumulated upstream
difference. The windowed perturbation (`simulate_plant(..., perturb=(i, t0,
t1, f))`) leaves history before t0 bit-identical to baseline — verified by
`test_crn_perturbation_isolated`.

## Status

`v3/process` is **still current** and complements v5 — it is the deep
failure-mode corpus (~20,000 ops per tool against v5's ~300), and it holds
the `holdout/` calibration set and the `firewall/` Wiener-process
generalisation set. `v3/flow` is superseded by v5. The claims tables above
are the specification: every element exists to enable one measurable claim,
and everything regenerates on fixed seeds.
